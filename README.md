# Gate1 提出物

社内問い合わせ管理システムの「ステータス変更・担当者割り当て」機能です。問い合わせ登録・一覧表示・ログイン機能は実装済みという前提で、詳細画面と更新APIを実装しています。

## 1. 起動手順

### 動作環境

- Node.js 22.5以上（`node:sqlite`を使用）
- npm（Node.jsに同梱）

外部パッケージは使用していません。

### 環境構築コマンド

```bash
git clone https://github.com/kurihara-vexum/NEXUS-Gate1.git
cd NEXUS-Gate1
npm install
```

### 起動コマンド

```bash
npm start
```

起動後、次のURLをブラウザで開きます。

- MEMBER：http://localhost:3000/inquiries/1?actorId=2
- ADMIN：http://localhost:3000/inquiries/1?actorId=1

初回起動時にSQLiteデータベース `data/nexus.sqlite` と確認用データが自動作成されます。`actorId=2` はMEMBERの佐藤 花子、`actorId=1` はADMINの山田 太郎として動作します。

画面右上の「初期状態に戻す」は、要件定義にはない動作確認用の補助機能です。押すと、操作中の権限にかかわらず、問い合わせ・担当者・変更履歴を確認用の初期データへ戻します。開いている同一オリジンの別タブにもリセットが通知されます。

### 自動テスト

```bash
npm test
```

## 2. 動作確認手順

以前の操作結果が残っている場合は、先に画面右上の「初期状態に戻す」を押してください。このボタンはテストを繰り返すために追加した要件外の補助機能です。

### ステータス変更

1. `http://localhost:3000/inquiries/1?actorId=2` を開く
2. 現在のステータスが「未対応」、担当者が「未割り当て」であることを確認する
3. 「対応中」を選択して「ステータスを変更」を押す
4. 「ステータスを「対応中」に変更しました。」と緑色で表示されることを確認する
5. ステータスが「対応中」になり、未割り当てだった担当者に操作者の「佐藤 花子」が自動設定され、変更履歴が1件増えることを確認する

不正遷移のエラー表示を確認する場合は、初期状態に戻して同画面の「完了」を選択し、「ステータスを変更」を押します。「このステータスへは変更できません。画面を再読み込みしてください。」と赤色で表示され、問い合わせと変更履歴が更新されないことを確認します。「未対応」から「完了」は本来遷移できない値ですが、エラー状態の提出画像を撮影できるよう、画面上に検証用の選択肢として表示しています。サーバー側では不正遷移として拒否します。

その他の状態は次のURLで確認できます。

- 対応中：`http://localhost:3000/inquiries/1?actorId=1`
  - 「保留」または「完了」に変更できる
  - 「完了」にすると `closed_at` に現在日時が保存される（画面には表示せず、`http://localhost:3000/inquiries/1?actorId=1` のJSONで確認する）
- 保留：`http://localhost:3000/inquiries/1?actorId=2`
  - 変更先には「対応中」だけが表示され、「完了」は表示されない
- 完了：`http://localhost:3000/inquiries/1?actorId=1`
  - 変更先には「対応中」だけが表示される
  - 「対応中」に戻すと `closed_at` が `null` になる（`http://localhost:3000/inquiries/1?actorId=1` のJSONで確認する）

すべての正常なステータス変更で、`updated_at` が更新され、変更履歴が1件登録されます。

### MEMBERの担当者割り当て

1. `http://localhost:3000/inquiries/1?actorId=2` を開く
2. 担当者候補にログイン中の「佐藤 花子」だけが表示されることを確認する
3. 「担当者を変更」を押し、自分が担当者になることを確認する
4. 担当者設定後はボタンが非活性となり、「担当者の変更は管理者に依頼してください」と表示されることを確認する

MEMBERは、未割り当ての問い合わせを自分に割り当てる操作だけが可能です。すでに担当者が設定されている問い合わせでは担当者変更セクションは表示されますが、変更ボタンは非活性になります。

### ADMINの担当者割り当て

1. `http://localhost:3000/inquiries/1?actorId=1` を開く
2. 「未割り当て」がプルダウンの先頭にあることを確認する
3. 有効ユーザーだけが氏名順で表示されることを確認する
4. 任意の有効ユーザーへ変更できることを確認する
5. ステータスがNEWの場合、担当者を「未割り当て」に戻せることを確認する

担当者の変更または未割り当てへの変更に成功すると、指定された成功メッセージが緑色で表示され、変更履歴が1件登録されます。無効ユーザーの指定、権限のない操作、DONE状態での担当者変更はサーバー側でも拒否されます。

### 表示ルール

- PENDING：`http://localhost:3000/inquiries/1?actorId=2`
  - ステータス変更先が「対応中」だけであること
  - 優先度「低」が灰色で表示されること
- DONE：`http://localhost:3000/inquiries/1?actorId=1`
  - ステータス変更先が「対応中」だけであること
  - 担当者変更ボタンが非活性であること
- 変更履歴が0件の場合、「変更履歴はありません」と表示されること
- 優先度が「高」は赤文字、「中」は黒文字、「低」は灰文字で表示されること
- コメントが201文字の場合、「コメントは200文字以内で入力してください。」と赤色で表示され、更新されないこと



## 3. 実装できなかった箇所

要件範囲内の未実装箇所はありません。

問い合わせ登録・一覧表示は実装済みという前提、本番用ログイン認証は今回の対象外です。そのため、確認環境ではURLの `actorId` でログインユーザーを切り替えています。

`closed_at` はデータベースへの保存とAPIでの返却まで実装しており、画面への表示要件がないため詳細画面には表示していません。

画面右上の「初期状態に戻す」は要件定義に含まれる機能ではありません。状態変更のテストを何度でも同じ初期条件から行えるよう、検証補助機能として追加実装しています。

## 4. セルフチェック結果

- [⚪︎] NEWの問い合わせで、変更先に「対応中」が表示される
- [⚪︎] NEWの問い合わせで「完了」に変更しようとしても弾かれる
- [⚪︎] DONEの問い合わせで「対応中」に戻せる
- [⚪︎] DONE → IN_PROGRESSのとき `closed_at` がNULLになる（http://localhost:3000/api/inquiries/1?actorId=2で確認）
- [⚪︎] NEW → IN_PROGRESSのとき、担当者未設定なら操作者が担当者になる
- [⚪︎] MEMBERで、他人が担当している問い合わせの担当者を変更しようとすると弾かれる
- [⚪︎] MEMBERで、未割り当ての問い合わせを自分に割り当てられる
- [⚪︎] ADMINで、担当者を未割り当てに戻せる（NEWのときのみ）
- [⚪︎] 無効ユーザーがプルダウンに出てこない
- [⚪︎] ステータス変更・担当者変更の両方で履歴が1件ずつ増える
- [⚪︎] コメントに201文字入れるとエラーメッセージが出る
- [⚪︎] メッセージ文言が仕様書と完全に一致している（句読点まで）
- [⚪︎] 履歴登録を意図的に失敗させると、本体の更新もロールバックされる

※確認後、各項目を○または×に置き換え、×の場合は理由を記載してください。

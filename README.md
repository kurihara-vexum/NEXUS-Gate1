# Gate1 提出物

社内問い合わせ管理システムの「ステータス変更・担当者割り当て」機能です。問い合わせ登録・一覧表示・ログイン機能は実装済みという前提で、詳細画面と更新APIを実装しています。

## 1. 起動手順

### 動作環境

- Node.js 22.5以上（`node:sqlite`を使用）
- 外部パッケージなし

### 起動コマンド

```bash
npm start
```

起動後、次のURLをブラウザで開きます。

- MEMBER：http://localhost:3000/inquiries/2?actorId=2
- ADMIN：http://localhost:3000/inquiries/1?actorId=1

初回起動時に `data/nexus.sqlite` と確認用データが自動作成されます。

### 自動テスト

```bash
npm test
```

## 2. 動作確認手順

### ステータス変更

1. `http://localhost:3000/inquiries/1?actorId=2` を開く
2. 現在のステータスが「未対応」であることを確認する
3. 「対応中」を選択して「ステータスを変更」を押す
4. 成功メッセージ、ステータス、担当者、変更履歴が更新されることを確認する

不正遷移を確認する場合は、初期状態の同画面で「完了」を選択します。「このステータスへは変更できません。画面を再読み込みしてください。」と表示され、更新されないことを確認します。

### MEMBERの担当者割り当て

1. `http://localhost:3000/inquiries/1?actorId=2` を開く
2. 担当者候補にログイン中の「佐藤 花子」だけが表示されることを確認する
3. 「担当者を変更」を押し、自分が担当者になることを確認する
4. 担当者設定後はボタンが非活性となり、「担当者の変更は管理者に依頼してください」と表示されることを確認する

### ADMINの担当者割り当て

1. `http://localhost:3000/inquiries/1?actorId=1` を開く
2. 「未割り当て」がプルダウンの先頭にあることを確認する
3. 有効ユーザーだけが氏名順で表示されることを確認する
4. 任意の有効ユーザーへ変更できることを確認する
5. ステータスがNEWの場合、担当者を「未割り当て」に戻せることを確認する

### 表示ルール

- PENDING：`http://localhost:3000/inquiries/3?actorId=2`
  - ステータス変更先が「対応中」だけであること
  - 優先度「低」が灰色で表示されること
- DONE：`http://localhost:3000/inquiries/4?actorId=1`
  - ステータス変更先が「対応中」だけであること
  - 担当者変更ボタンが非活性であること
- 変更履歴が0件の場合、「変更履歴はありません」と表示されること

## 4. セルフチェック結果

- [ ] NEWの問い合わせで、変更先に「対応中」が表示される
- [ ] NEWの問い合わせで「完了」に変更しようとしても弾かれる
- [ ] DONEの問い合わせで「対応中」に戻せる
- [ ] DONE → IN_PROGRESSのとき `closed_at` がNULLになる
- [ ] NEW → IN_PROGRESSのとき、担当者未設定なら操作者が担当者になる
- [ ] MEMBERで、他人が担当している問い合わせの担当者を変更しようとすると弾かれる
- [ ] MEMBERで、未割り当ての問い合わせを自分に割り当てられる
- [ ] ADMINで、担当者を未割り当てに戻せる（NEWのときのみ）
- [ ] 無効ユーザーがプルダウンに出てこない
- [ ] ステータス変更・担当者変更の両方で履歴が1件ずつ増える

- [ ] メッセージ文言が仕様書と完全に一致している（句読点まで）
